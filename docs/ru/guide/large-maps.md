# Большие карты

На одной карте помещаются десятки тысяч сущностей — если ни карта, ни приложение не делают работу, пропорциональную им
всем, на каждое мелкое изменение. Свою половину карта берёт на себя; здесь описано, что она делает сама и что остаётся
приложению.

## Что карта делает сама

**Отсечение по области видимости.** Начиная с `virtualize` узлов (по умолчанию 300) карта держит собственный
пространственный индекс и отдаёт Vue Flow только то, что на экране, плюс полэкрана запаса — и оба конца каждой связи,
которая через него проходит. Размеры узлов известны до отрисовки, поэтому монтировать узел, чтобы узнать, где он, не
нужно. Встроенный `onlyRenderVisibleElements` Vue Flow при этом выключается: неизмеренный узел для него 0×0 и считается
видимым, из-за чего первый кадр — и каждое раскрытие группы — монтировал всё.

**Точки на canvas при отдалении.** Ниже `lodThreshold` виртуализированная карта рисует узлы точками, а связи линиями на
одном `<canvas>` (`lodCanvas`, по умолчанию включён). Цвета подчиняются тем же правилам, что и DOM-узлы, — статус,
выделение, совпадения поиска, затемнение, заражение — и по-прежнему берутся из токенов `--vam-*`. Клик по точке выбирает
узел и открывает его окно, по точке группы — раскрывает группу.

**Группы раскрываются порциями.** Раскрытая группа показывает `pageSize` участников (200), остальные ждут в узле
«ещё». См. [Свёртка групп](./collapse#раскрытие-большои-группы).

**Раскладка запускается только при смене структуры.** Новый массив `entities` с теми же id и родителями в том же
порядке — переименованный актив, сменившийся статус, сдвинутый узел — переиспользует индексы графа и ничего заново не
раскладывает. Добавление, удаление, смена родителя или переадресация связи — раскладывают.

**Поиск готовит каждую сущность один раз.** Поля в нижнем регистре и найденные в них адреса хранятся рядом с
сущностью, поэтому разбор оплачивает только первый запрос: поиск по CIDR на 100 000 сущностей — было около 160 мс на
нажатие, стало около 25 мс.

**Обзорная карта — три элемента.** Начиная с 500 узлов `MiniMap` рисует по одному пути на вид узла, а не прямоугольник
на каждый.

```vue
<AssetMap
  :entities="entities"
  :links="links"
  :virtualize="true"
  :lod-threshold="0.4"
  :collapse="{ pageSize: 100 }"
/>
```

## Как отдавать данные карте

Карта не копирует и не меняет `entities`; насколько дёшево она реагирует на изменение, зависит от того, как оно
приходит.

- **Не делайте большие наборы глубоко реактивными.** `ref` над сотней тысяч записей оборачивает каждую в прокси, и
  каждое чтение поля идёт через него. Держите их в `shallowRef` (или помечайте записи `markRaw`) и при изменении
  присваивайте новый массив.
- **Правьте одну запись через `updateEntity`.** Для статуса или подписи вызовите метод карты с новым объектом вместо
  сборки нового массива. Ничего не раскладывается заново, ничего не перемонтируется, открытое окно показывает правку:

  ```ts
  const map = ref<AssetMapExposed<Asset>>()
  map.value?.updateEntity({ ...entity, status: 'offline' })
  ```

  Подходит для записей, уже стоящих на карте, с тем же `parentId`. Замена действует до прихода следующего массива
  `entities`, поэтому своё хранилище держите в согласии с ней.

- **Храните позиции отдельно от записей.** Привяжите `v-model:positions` (или слушайте `node-move`) и сохраняйте
  позиции своим запросом, пачками и с задержкой, — а не записью в актив с сохранением всей записи. Тогда перетаскивание
  стоит одного ключа в одном объекте, а не новой версии актива и нового массива.
- **Импортируйте одним присваиванием.** Тысяча записей, созданных по одной и каждая добавленная в хранилище, — это
  тысяча пересборок карты. Соберите пачку, затем присвойте её один раз.
- **Ищите записи по id через `Map`.** `array.find` в цикле по соседям квадратичен на большой схеме. В `getGraph()` уже
  есть `entities`, `adjacency` и `links`, проиндексированные по id.

## Раскладка вне главного потока

Dagre в главном потоке отказывается от графов больше `maxNodes` (2 000). Чтобы разложить больше или не замораживать
вкладку на время расчёта, запустите его в воркере. Файл воркера принадлежит приложению — только его сборщик умеет
выпустить воркер:

```ts
// layout.worker.ts
import { exposeLayoutEngine } from 'vue-asset-map/layout-worker'
import { dagreLayout } from 'vue-asset-map/layout-dagre'

exposeLayoutEngine(dagreLayout)
```

```ts
// там, где карта
import { createWorkerLayout } from 'vue-asset-map'

const dagreOffThread = createWorkerLayout(
  'dagre',
  () => new Worker(new URL('./layout.worker.ts', import.meta.url), { type: 'module' }),
)

const layout = { engine: dagreOffThread, options: { rankdir: 'LR', maxNodes: 8000 } }
```

Воркер создаётся при первом запуске и переиспользуется. Запуск, который карте больше не нужен, — сменился вид,
поменялись данные — завершает воркер: синхронный алгоритм иначе не остановить; следующий запуск создаёт новый. Опции
должны пережить `postMessage`, поэтому функций в них быть не может.

## Чего отсечение не умеет

- **Узел-хаб на экране тянет за собой соседей.** Каждая связь, пересекающая экран, монтируется с обоими концами, так что
  узел с десятью тысячами связей смонтирует десять тысяч дальних концов. Такие хабы держит в узде свёртка.
- **`fitView` на виртуализированной карте подгоняет по индексу, а не по DOM.** Это по-прежнему вся карта — просто
  теперь она не зависит от того, что сейчас смонтировано.
- **Переход стрелками к отсечённому узлу сначала сдвигает вид**, а фокус ставит, когда узел смонтирован.
